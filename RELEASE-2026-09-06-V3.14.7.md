## Failure mechanism and repair

The old click handler reloaded after 900ms without confirming that the waiting
worker controlled the page. Network-first navigation could then serve old HTML
alongside the new worker's cached scripts. Controller changes also lacked a
page/worker build comparison, allowing a prompt for an already displayed build.
These are confirmed source and controlled-test failure paths; the screenshot
alone cannot establish the exact worker state on the user's device.

The page and worker now exchange an explicit build identity. A requested update
reloads only after controller replacement or confirmed ownership; a timeout
offers retry without reloading the old controller. Matching builds suppress the
phantom prompt. Each installed worker serves its own precached HTML together
with its shared scripts. Precache bypasses the HTTP cache and rejects mismatched
HTML/build stamps before activation. Registration uses updateViaCache=none.

Running measurements and pending Stop finalizations still block updates. Hidden
controls remain inert. Local storage, outboxes, exact recorded time, authentication,
catalogs and completion ownership are unchanged (C-TRACK-01/02, C-SYNC-01/02,
C-CATALOG-01). No Firestore rules, Automation runtime, CSS or embed changes.
