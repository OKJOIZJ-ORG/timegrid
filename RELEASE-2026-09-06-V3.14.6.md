# TimeGrid v3.14.6 — historical measured-block planning links

Status: Deployed and live-verified on 2026-09-06.

Authority: D-027. The user requested repair of historical event memo linking and
directed future verified TimeGrid implementation changes to deploy automatically
without a second approval. Read-only requests remain read-only.

## Defects and repair

- Candidate date: the event editor previously called `noteCandidates()` with the
  wall-clock date. It now passes the recorded event date, so a 2026-09-05 block
  shows only that day's Todo and Routine instances.
- Apply path: the event dialog previously reused the Tracker callback, which
  changed Tracker state rather than event-edit state. The dialog now owns its
  selected candidate, query and apply callback.
- Persistence: metadata-only and minute-time save paths now persist the selected
  stable `todoId` or `routineId`. Free note, Todo link and Routine link remain
  mutually exclusive. Typing a different free note detaches the prior link.
- Completion: linking measured time does not set `done` or write
  `statusMutations`; the existing completion owner is unchanged.

Exact event IDs, `startTs`, `endTs`, logical-span outer bounds and continuity
reconciliation are preserved. No Firestore rule, schema/protocol, catalog,
CSS/layout, Notion embed or Automation runtime changed.
