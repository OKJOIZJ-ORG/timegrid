# TimeGrid v3.14.8 — static-only worker and passive updates

Status: Deployed; public assets and the affected authenticated Chrome tab verified.
Authority: the user reported continued update failure on v3.14.7 and questioned
the need for its button. This repair removes that control and preserves safe
measurement/storage behavior. D-027 authorizes verified deployment.

## Evidence and responsible layer

The actual affected Chrome tab displayed v3.14.7, but its active controller did
not answer GET_VERSION, the v3.14.6 caches remained, and the installed waiting
worker answered v3.14.7. The displayed failure was real, not merely stale toast
text. The preceding v3.14.7 isolated test omitted external SDKs and did not cover
the live network request lifetime; its passing result did not establish repair
of the user's authenticated session.

The old worker intercepted every cross-origin GET and awaited cache.put before
returning its response. A long-lived response keeps that fetch event pending.
The [Service Worker Try Activate algorithm](https://www.w3.org/TR/service-workers/#try-activate)
requires the old worker to have no pending events even with the skip-waiting flag.
Repeated UI retries do not remove that condition. The precise outstanding request
in the user's old worker was not exported or inferred from a private request URL.

## Repair and preserved behavior

- The worker now handles only its own scoped navigation and declared static
  app-shell files. Firestore, authentication, external SDKs, unknown endpoints and
  sibling apps bypass it entirely. No live data response is put into app caches.
- The complete update banner, retry button, error prose and CSS were removed.
  Updates prepare quietly. A prepared worker can activate during an untouched
  entry or a safe hidden transition. The active foreground task is not interrupted.
- Only an untouched, unblocked entry may reload after an identified different
  controller; a per-target session guard prevents a reload loop. Unknown replies
  never authorize a timed reload. Input, pointer/keyboard interaction, open editors,
  running measurements and pending Stop finalizations defer automatic reload.
- Activated-shell HTML, installation build checks and fresh cache identities
  remain. C-TRACK-01/02, C-SYNC-01/02 and C-CATALOG-01 data contracts are preserved.
  No Firestore rules, schema, measurements, outboxes or Automation runtime changes.

## Verification and limits

Static-boundary and passive-update guards passed locally: non-shell requests
never enter respondWith/cache handling; pending activation does not trigger a
timer reload; typing cancels entry reload; running/pending Stop and open-editor
guards hold; becoming idle does not interrupt the current screen.
Actual Edge long-stream regression passed: v3.14.6 held v3.14.7 waiting until
the server ended its response; v3.14.8 allowed its exact successor to activate
while the same cross-origin response remained open. Native iPhone/WebKit and authenticated multi-device E2E are
outside the executed acceptance scope.

- All 131 Node checks across 28 programs passed; inline/SW syntax and U+FFFD=0.
- Passive Chromium cases passed different-build entry reload, same-build retention,
  no timer reload, input cancellation, running/pending Stop and editor deferral.
- Actual v3.14.6-to-v3.14.8 entry upgrade passed with 1600ms delayed activation:
  no early reload, identified candidate control, no redundant same-build reload,
  then repeated reload from the activated shell despite stale origin HTML.
- Four real-bootstrap contexts passed at 390px/1280px with GSAP enabled/disabled,
  local exact Start/Stop, persistence and offline shell reload. Removed update
  CSS/DOM markers are absent; editor selectors match the existing open classes.

## Delivery and recovery

Footer/build: v3.14.8 / timegrid-v3.14.8-20260906.
Prefer forward repair with a new cache identity. Never clear browser storage,
measurements, pending receipts or outboxes. An already executing legacy worker
must release its outstanding requests before replacement; a safe page exit and
return may be needed once for that migration. New source deployment cannot
retroactively change the old worker's fetch handler. Preserve the independent
Automation installation and historical untracked v3.12.65 artifacts.
